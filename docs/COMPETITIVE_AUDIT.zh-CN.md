# Signal Field 竞品与产品差距审查

**审查日期：** 2026-07-27
**结论：** Signal Field 不应扩张成通用剪辑器或预设播放器。最有辨识度、也最可落地的方向是：**面向独立音乐人的本地优先生成式 3D 歌词视觉视频工具**。

## 当前产品到底是什么

Signal Field 已经不是单纯的粒子演示。它能在本机读取一首歌，分析强弱、频谱、变化、速度和段落，自动生成可编辑的 3D 场景时间线；随后加入标题、歌词和节拍剪辑，并通过同一套合成逻辑进行预览与 H.264 / ProRes 导出。

当前真实完成度可概括为：

- **已完成：** 本地音乐分析、3 种导演模板、3 种真实预览画幅、4 种粒子风格、场景项目、标题/LRC/节拍 Production Spec、波形精修、撤销/重做、无媒体工程恢复、桌面渲染预检与队列、失败重试、Finder 定位、真实 FFmpeg 视频验证，以及开发态/打包态共用的 worker 启动链。
- **半完成：** FFmpeg/ffprobe 尚未随应用交付；安装包 verifier 已有，但每个发布成品仍需在内部/APFS 构建目录完成真实验证；队列本身尚不跨应用重启持久化。
- **不应宣称：** 网页直接导出 MP4、已有签名公证安装包、自动听写歌词、逐字卡拉 OK、完整非线性剪辑器。

| --- | --- | --- |

| [Musicvid.org](https://musicvid.org/) | 浏览器内模板、图层/自动化和本地渲染 | 证明本地创作有需求，但官方 About 已说明项目不再积极开发；其导出也受浏览器内存约束。 |
| [Vizzy](https://vizzy.io/) | 社区模板、图层、自动化、歌词视频和成熟时间轴 | 编辑深度明显领先；Signal Field 不应因此复制通用图层系统，而应保持自动生成和 3D 共振特色。 |
| [Specterr](https://specterr.com/music-visualizer/) | 清晰的“选预设→上传→改品牌→云端导出”四步结果流程 | 首次成功路径更短，标题、图像和品牌配置更直白；但不是本地优先。 |

| [VEED Music Visualizer](https://www.veed.io/tools/music-visualizer) | 波形模板、字幕、通用拖放时间轴和社交画幅 | 易用性和编辑完整性领先；它是云端通用编辑器，Signal Field 的差异应是本地隐私和程序化 3D。 |

厂商自报的用户量、素材量和评价只作为产品成熟度线索，不当作独立审计数据。开源项目的 star 数也会持续变化，因此本审查不把某个瞬时数字作为路线决策依据。

## 真正的差距

### P0：交付可信度

1. 每个 macOS 发布候选都必须运行安装包 worker verifier 与真实编码；签名、公证和 Apple Developer 身份仍属于发布方工作。
2. FFmpeg/ffprobe 目前采用启动预检加明确安装指引，尚不是零配置内置交付。
3. 网页只能下载 Production Spec；公开文案必须继续明确这一点。

### P1：第一次成功的摩擦

1. 竞品普遍允许用户直接粘贴歌词或自动生成字幕；此前 Signal Field 强制用户先准备带时间戳的 LRC。
2. 缺少可直接打开的 Starter Project 和当前版本生成的视频案例。
3. 真实画幅已经落地；后续差距转为 Starter Project、字体一致性和更直接的首次成片示例。

### P2：成熟编辑体验

数值检查器、跨重启持久化队列、长歌标记虚拟化、字体打包和真实设备矩阵仍需逐步完成。撤销/重做、失败重试和 Finder 定位已经补齐。这些能力应继续服务核心成片结果，而不是把产品推成完整 NLE。

## 选择的专一路线

核心承诺只保留一句：

> 上传歌曲和歌词，在本机自动生成一条可精修、可导出的 3D 粒子歌词视频。

因此明确不做：

- MilkDrop 预设市场；
- 库存视频素材平台；
- 云端通用剪辑和团队协作；
- 联网歌词搜索；
- 本阶段的全自动语音转写和逐字卡拉 OK。

## 本轮实施：纯文本歌词时间初稿

本轮新增的 `app/lyric-timing.js` 接受每行一句的纯文本歌词，复用已经生成的本地音乐分析：

- 估计可用的起止区间；
- 根据音乐段落、行长和可信节拍分配行级开始/结束时间；
- 生成严格有序、互不重叠的 canonical `ProductionSpec.lyrics`；
- 把结果转回标准 LRC，并直接显示在现有波形时间轴；
- 明确标记为“时间初稿”，最高参考置信度被限制为 60%，不冒充人声识别或 forced alignment。

这项能力减少了“先去别处制作 LRC”的首条成片阻力，同时不上传音频、不增加运行时依赖，也不扩张成通用编辑器。

## 后续顺序

1. **P0：发行候选验证**——在 APFS/内部磁盘构建成品，执行安装包 worker verifier、真实短片编码、签名与公证检查。
2. **P1：零配置编码交付决策**——评估内置 FFmpeg 的体积、更新和许可证成本；在此之前保留明确预检。
3. **P1：首次成功样例**——提供当前版本生成的 Starter Project 与短视频，不使用继承宣传素材。
4. **P2：长项目可靠性**——队列跨重启恢复、长歌词虚拟化和真实设备矩阵。

除非核心成片数据证明有必要，不再继续增加独立实验室、通用图层或粒子模式。
